# 하네스 보고 형식 (8단계)

검사 결과는 **매번 같은 형식**으로 낸다. 가장 중요한 건 "어디까지 확인했는지"다 — "통과"만 있으면 가짜 서버로 확인한 것을 진짜 저장된 것으로 착각하게 된다.

## 형식

```
판정: ✅ 통과 (사람 확인 1건)        ← 첫 줄. ✅ 통과 / ❌ 실패 / ⚠️ 부분 통과

확인한 것
- R1 ✅ 화면까지
- R2 ✅ 화면까지
- R3 ✅ 요청 내용까지 (서버는 가짜)
- R4 ❌ 서버 오류 시 입력값이 사라짐 — src/signup/form.tsx:42

사람이 확인할 것
- [ ] R3: 실제 서버에서 중복 이메일 응답이 오는지

첨부: 캡처 4장 (artifacts/screens/signup/)
```

## 확인 깊이 (얕은 → 깊은)

| 표기 | 뜻 |
| --- | --- |
| 코드만 | 코드를 읽어 보니 그럴 것 같다. 실행하지 않음 |
| 단위 테스트까지 | 로직 테스트가 통과 |
| 요청 내용까지 (서버는 가짜) | 보낸 요청은 검사했지만 응답은 가짜 |
| 화면까지 | 실제 렌더링·캡처로 확인 |
| 실제 저장까지 | 진짜 DB/서버에 반영된 것까지 확인 |

## 규칙

- 판정은 가장 나쁜 결과를 따른다. 하나라도 ❌면 전체 ❌, 미확인 항목이 있으면 최대 ⚠️.
- ❌에는 근거(파일:줄, 실패한 테스트 이름, 출력 요약)를 붙인다.
- 확인 못 한 것을 ✅로 쓰지 않는다. "사람이 확인할 것"으로 옮긴다.
- 규칙 문서가 없으면 규칙 번호 대신 검사 항목 이름을 쓰되, 형식은 그대로 유지한다.
