LLM 결과처럼 매번 조금씩 다른 기능은 맞다/틀리다 대신 **점수**로 본다. 대상: `$ARGUMENTS`.

> AI 기능이 없는 프로젝트면 이 단계는 건너뛰라고 말하고 멈춘다.

## 순서

1. **대상 찾기**: LLM을 호출하는 서비스/함수를 찾는다. eval은 운영 코드와 **같은 함수**를 태워야 한다 (프롬프트를 복사한 별도 스크립트 금지).
2. **골든 세트 만들기**: `eval/<기능>/fixtures/` 에 입력과 정답 쌍 10~30개.
   - `<이름>.input.*` + `<이름>.expected.json`
   - 쉬운 케이스만 넣지 않는다: 빈 값, 애매한 값, 형식이 깨진 입력, 실제 실패 사례를 섞는다.
   - 정답은 사람이 확인한다. AI가 만든 정답 초안은 사용자에게 검토받는다.
3. **채점기 붙이기**: `${CLAUDE_PLUGIN_ROOT}/templates/eval/score.mjs`를 프로젝트로 복사해 시작점으로 쓴다 (필드별 정확도, 문자열 정규화, 배열 F1). 프로젝트 언어에 맞게 옮겨도 된다.
   - 채점 로직 자체에 단위 테스트를 붙인다 (결정적이므로 check에 넣을 수 있음).
4. **실행 명령**: `eval` 스크립트(예: `npm run eval`)로 전부 돌려 필드별 정확도 표와 실패 케이스 목록을 출력한다. 결과를 `eval/<기능>/baseline.json`에 저장해 다음 실행과 비교한다.
5. **루프 규칙 기록**: 프로젝트 지시문(CLAUDE.md 등)에 한 줄 추가를 제안한다:
   "프롬프트/스키마를 바꾸면 eval을 돌려 baseline보다 점수가 떨어지지 않는지 확인하고, 운영 실패 사례는 fixtures에 추가한다."

## 주의

- eval은 느리고 비용이 들 수 있으니 **Stop 훅/CI에 넣지 않는다.** 훅에는 채점기 단위 테스트만.
- API 키가 없으면 실행을 건너뛰되 "건너뜀"을 명확히 출력한다 (조용히 통과 금지).
