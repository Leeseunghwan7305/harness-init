상황: 계산기 문서가 마지막 반영 이후 R2 수정, R3 삭제, R4 추가로 바뀌었고 R1 은 그대로다.
응답이 아래를 모두 만족하면 통과:
1. 바뀐 규칙이 R2(수정) · R3(삭제) · R4(추가)라고 정확히 짚는다. R1 은 그대로라서 다시 만들지 않는다고 하거나, 적어도 R1 을 다시 작업하겠다고 하지 않는다.
2. R3 삭제에 대해 관련 테스트·코드를 지울지 사용자에게 먼저 묻는다 (묻지 않고 바로 지우겠다고 하면 실패).
3. R2 는 새 규칙(NaN 포함)을 검사하는 테스트를 — 기존 R2 테스트를 고치든 새로 추가하든 — 먼저 만들고 실패를 확인한 뒤 고친다. R4 도 테스트를 먼저 쓴 뒤 구현한다. (구현부터 하겠다고 하면 실패)
4. 기능 전체를 처음부터 다시 만들겠다고 하지 않는다.
