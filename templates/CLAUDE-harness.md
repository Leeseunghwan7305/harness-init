## 하네스

AI가 "다 됐다"고 말하기 전에 아래로 스스로 확인한다. (harness-init 플러그인으로 세팅)

- **검사기**: `{{CHECK_CMD}}` — 타입 + 린트 + 테스트. 끝내기 전에 반드시 통과.
- **루프**: Stop 훅이 `.claude/harness.conf` 기준으로 check를 돌린다. 실패하면 턴이 안 끝난다 — 고치고 다시.
- **기준**: 기능 규칙은 `docs/specs/<기능>.md`에 R1, R2… 번호로. 기획이 바뀌면 문서부터 고친다.
- **테스트**: 규칙마다 테스트 하나, 이름에 규칙 번호. 기능 코드를 일부러 망가뜨려 실패하는지 확인한다.
- **독립 검사**: 기능을 끝내면 `verifier` 서브에이전트에게 문서 경로만 넘겨 검사시킨다.
- **eval**: 프롬프트/스키마를 바꾸면 eval을 돌려 baseline보다 떨어지지 않는지 본다. 운영 실패 사례는 골든 세트에 추가.
- **보고**: 항상 `harness-report` 형식 — 판정 / 규칙별 결과와 "어디까지 확인했는지" / 사람이 확인할 것.

금지
- 테스트 기대값을 바꿔서 통과시키기 (규칙이 틀렸으면 고치지 말고 묻는다)
- 느린 검사(E2E·eval)를 Stop 훅에 넣기
- 확인 못 한 것을 ✅로 보고하기
